“保存为空间 API”在当前页面中的操作名为“发布为空间 API”。创建向导也支持勾选“添加到空间 API”并随创建保存；本次优先采用正式保存后的入口，使两项操作的先后关系清晰。

空间 API 复用接口定义和数据结构，不共享连接凭证、同步计划或业务数据。复用时重新填写连接凭证；演示中不展示真实凭证明文。API名称与说明均必填。不要误把数据对象的查询接口或Pipe Studio保存操作当作空间API模板发布。

模型输出曾出现JSON语法错误及未提交工具，保留失败后正常重试恢复。演示预备配置完成草稿；不要现场无限重试，也不要把人工补主键讲成AI已自动确认。所有分幕通过与连续25分钟计时分开记录。

## 右侧助手提示语

- 解释：“解释当前选中接口的鉴权、分页、参数来源和数据表，不修改配置。”
- 诊断：“根据已有配置和验证记录，指出缺项或失败原因，并给出页面查看位置；不要发真实请求。”
- 修改：“仅将当前接口显示名称改为‘客户业务列表’，其他配置不变。”
- 补充：“新显示名称是“客户业务列表”。仅补充原操作所缺名称，其他配置保持，不验证接口。”

模型存在不确定输出；每次先看范围与实际差异。演示从“自动识别”发起缺少名称的请求，助手询问后保持原处理方式，输入补充文本并发送；不要点击“发起新问题”或切换处理方式，以免另开请求。“补齐后继续原操作”按钮用于页面配置已人工补齐后的重读，不会自动提交输入框中的新名称。没有确定回执时先查询状态，不反复新发同一请求。不要把修改配置与“修复并验证”混用；现场不增加未经确认的真实验证范围。
